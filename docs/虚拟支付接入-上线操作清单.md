## 0. 先认清一件事：真实支付必须有服务端

`wx.requestVirtualPayment` 只负责拉起支付，下面三件事只能在后端做：

1. 用 `wx.login` 的 `code` 换 `session_key`（用户态签名）
2. 用 AppKey 算 `paySig`（支付签名）
3. 接收发货推送 / 调 `/xpay/query_order` 查单，给用户加权益

本项目使用**微信云开发 CloudBase**，6 个云函数已写好：

| 云函数 | 作用 | 必需环境变量 |
|---|---|---|
| `login` | 返回 openid / 管理员判定 | `ADMIN_OPENIDS`（可选） |
| `createOrder` | code→session_key，生成 signData + paySig + signature，落单 | `OFFER_ID` `APP_KEY` `APPSECRET` `PAY_ENV` |
| `onDelivered` | 接收 `xpay_goods_deliver_notify`，幂等发货 | 无 |
| `queryOrder` | `/xpay/query_order` 查单，补发货 | `OFFER_ID` `APP_KEY` `APPSECRET` `PAY_ENV` |
| `getEntitlement` | 查权益（包月 / 分钟） | 无 |
| `consume` | 处理成功后扣分钟 | 无 |

## 1. 开通云开发环境

1. 微信开发者工具 → 顶部「云开发」→ 开通 / 新建环境（按量计费，有免费额度）
2. 记下**环境 ID**（形如 `cloud1-xxxxxxxx`）
3. 填进 `miniprogram/config.js`：
   ```js
   CLOUD_ENV: 'cloud1-xxxxxxxx',
   ```
   > 只有一个环境时留空也能跑，但多环境必须填；填了也更不容易连错。

---

## 2. 部署云函数

在项目根目录执行（把 `ENV_ID` 换成第 1 步的环境 ID）：

```bash
CLI=/Applications/wechatwebdevtools.app/Contents/MacOS/cli
"$CLI" cloud functions deploy \
  --env ENV_ID \
  --names login createOrder onDelivered queryOrder getEntitlement consume \
  --project /Users/kongkang/Developer/tiao-diao \
  --remote-npm-install
```

部署后在「云开发 → 云函数」里确认 6 个函数都在、区域/运行时正常。

## 3. 填云函数环境变量

云开发控制台 → 云函数 → 选中函数 → 配置 → 环境变量。

### `createOrder` 与 `queryOrder` 都必须填

| 变量 | 值 | 说明 |
|---|---|---|
| `OFFER_ID` | 虚拟支付 OfferID | MP 后台 → 支付与交易 → 虚拟支付 → 基本配置 |
| `APP_KEY` | **现网 AppKey** | 同上；`PAY_ENV=0` 用这个 |
| `PAY_ENV` | `0` | 体验版/正式版只能是 0；沙箱 1 仅开发者工具 |
| `APPSECRET` | 小程序 AppSecret | MP 后台 → 开发管理 → 开发设置 |
| `APPID` | `wx0e7879a4c7d37c39` | 可不填，默认取云函数上下文 |
| `APP_KEY_SANDBOX` | 沙箱 AppKey | 仅当 `PAY_ENV=1` 时使用，可选 |

> ⚠️ `AppKey` / `AppSecret` 只放云函数环境变量，**不要写进代码、不要提交到 git**。

### `login`（可选）

| 变量 | 值 |
|---|---|
| `ADMIN_OPENIDS` | 管理员 openid，逗号分隔；管理页可复制自己的 openid |

## 4. 配置发货推送（关键）

**推荐：云开发消息推送 → 云函数**（不需要自己搭 HTTP、不需要 Token/AESKey）

1. 云开发控制台 → 设置 → 其他设置 → 消息推送
2. 推送模式选「云函数」
3. 添加消息推送配置：
   - 消息类型：`event`
   - 事件类型：`xpay_goods_deliver_notify`
   - 云函数环境：第 1 步的环境
   - 云函数：`onDelivered`
4. 保存

发货推送是**唯一可信的到账依据**；前端 `success` 回调可能丢失，代码里只把它当弱确认。

> 如果不用云开发消息推送，也可以走 MP 后台「开发管理 → 消息推送」配 HTTPS URL，
> `onDelivered` 同时兼容 JSON / XML body，但需要自己处理 URL 验签。

## 5. 创建并发布 2 个道具

MP 后台 → 支付与交易 → 虚拟支付 → 道具管理。

| 道具 ID | 名称 | 价格（分） | 权益 |
|---|---|---|---|
| `pkg_60` | 60 分钟 | `100` | 加 60 分钟（促销：1 元） |
| `pkg_month` | 包月 | `990` | 顺延 30 天 |

要求：

- 道具 ID、价格必须与 `miniprogram/config.js` 的 `PRODUCTS`
  和 `cloudfunctions/createOrder/index.js` 的 `PRODUCTS` **完全一致**，否则报 `-15013`
- 创建后必须**发布**；发布后约 10 分钟生效（期间报 `-15014`）
- iOS 单笔最低 1 元（`pkg_60=100 分` 刚好满足）

## 6. iOS 支付（要测 iPhone 才需要）

1. MP 后台配置**小程序简称**（账号设置 → 基本信息）；Apple 支付要展示 display name
2. 虚拟支付 → 基本配置 → 开通**苹果 IAP 支付**
3. 用户条件：iOS 15+、微信 8.0.68+、中国大陆 App Store 账户
4. 沙箱环境在 iOS 上不可用，iPhone 只能走现网（真实扣款）

代码已做 iOS 版本 / 金额校验；不满足时会给明确提示，不会直接报错。

## 7. 数据库集合

首次调用会自动创建以下集合（云函数有管理员权限）：

- `orders`：订单（`outTradeNo` 幂等锚点）
- `users`：权益（`minutes` / `monthlyUntil`）
- `deliveries`：发货锁（`_id = outTradeNo`，防重复到账）
- `consume_logs`：扣减流水（对账用）

如果自动创建失败，在云开发控制台手动建同名集合即可。

## 8. 上线前必须改的开关

`miniprogram/config.js`：

```js
PAY_ENABLED: true,        // 已开
CLOUD_LOGIN_ENABLED: true,
CLOUD_ENV: 'cloud1-xxx',  // 第 1 步的环境 ID
PAY_OFFLINE_FREE: false,  // ⚠️ 真实收款前必须改 false
```

`PAY_OFFLINE_FREE` 当前为 `true`：云服务不可达时按内测免费放行，保证 App 可用。
**开始真实收款前必须改 false**，否则断网/云故障时会被白用。

## 9. 真机验证清单

用 1 元档（`pkg_60`）测，成本最低：

- [ ] 买分钟页 → 立即购买 → 拉起微信支付/Apple 支付
- [ ] 支付成功 → 回到 App → 「我的」页显示 10 分钟
- [ ] 断网/取消支付 → 提示清楚，不重复扣款
- [ ] 同一订单重复推送 → 只到账一次（看 `deliveries` 集合只有一条）
- [ ] 支付后不返回 App（杀进程）→ 再打开，「我的」页仍能看到权益
      （发货推送已到；若没到，前端轮询超时会调 `queryOrder` 补发）
- [ ] 余额不足 → 弹「分钟数不够了」→ 去买分钟
- [ ] 包月购买 → 显示剩余天数，30 天内不再扣分钟
- [ ] iPhone：iOS 15+ / 微信 8.0.68+；低于版本有明确提示

## 10. 常见错误码对照

| 错误码 | 含义 | 处理 |
|---|---|---|
| `-2` | 用户取消 | 不提示，正常返回 |
| `-15005` | signature 错误 | session_key/code 问题；确认 `code` 新鲜且只用了 1 次 |
| `-15006` | paySig 错误 | 确认 AppKey 与 `env` 匹配；`signData` 前后端完全一致 |
| `-15007` | session_key 过期 | 重新 `wx.login` 再下单 |
| `-15010` | 道具未发布 | 去后台发布道具 |
| `-15011` | 现网用了沙箱 | `PAY_ENV` 改 0 |
| `-15013` | 价格不一致 | 三处价格同步：config / createOrder / MP 后台 |
| `-15014` | 道具发布未生效 | 等约 10 分钟 |
| `-15016` | signData 格式错误 | 检查字段类型：`offerId` 必须字符串、`goodsPrice` 数字 |
