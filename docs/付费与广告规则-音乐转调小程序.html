一、阶梯规则（已按"四舍五入"定稿）

统一算法（两行代码，广告数与付费金额共用同一套口径）：

计费分钟 M = max(1, Math.round(秒 / 60))   // 四舍五入到分钟，最少 1 分钟
广告数   = Math.ceil(M / 3)                 // 每 3 分钟 1 个广告
付费金额 = M × 0.1 元

时长来源 = 解码后的 AudioBuffer.duration（秒），精确可靠。

二、付费功能：有一条硬约束必须绕开

约束 1（合规）：卖"解锁权益"不能用普通微信支付。
自 2026 年 4 月 1 日起，微信小程序要求：凡在小程序内售卖虚拟商品/服务（解锁功能、额度、会员都算），必须全终端接入官方「虚拟支付」wx.requestVirtualPayment，不得再用 wx.requestPayment，也不得引导用户去公众号/H5/App 付款。违规会被风险提醒、限制功能甚至终止服务；审核也会直接打回（这是目前最常见的小程序被拒原因之一）。
约束 2（苹果）：iOS 端内购最低价格点是 ¥1。
虚拟支付在 iOS 端走的是 Apple IAP 通道，而苹果中国区的内购价格档位最低 ¥1（1~10 元之间每 0.5 元一档）。也就是说 ¥0.1 / ¥0.3 / ¥0.5 / ¥0.8 这种小额订单，在 iPhone 上根本发不出去。安卓端不受此限，但你不可能只做安卓。
约束 3（平台）：价格必须后台预先配置，不能前端传任意金额。
虚拟支付的道具（productId + 价格）要在 MP 后台配好并发布，支付时校验 productId 与 goodsPrice 完全一致，不一致直接报错。所以"每次按歌曲时长算出一个新价格"这种动态定价，在道具模式下做不到。

✅ 推荐方案：改成「分钟额度包」，单价仍是 0.1 元/分钟

用户先买额度，转歌时按分钟扣额度。你定的 0.1 元/分钟的单价完全保留，用户感受到的价格一分没变，只是从"每次单独付 0.5 元"变成"买 1 块钱的额度，够转 10 分钟的歌"。

三、这对"纯本地算力"有影响吗？没有

音频处理依然 100% 在手机上跑，一首歌的 PCM 数据一刻都不会离开设备。需要走网络的只有「订单、签名、余额」这几 KB 的数据。

但虚拟支付强制要求服务端：AppKey 和 session_key 绝不能出现在前端代码里，paySig / signature 两个签名必须在服务端算。所以要配一个极轻量的后端。

推荐用微信云开发（CloudBase）：云函数 + 云数据库，不用买服务器、不用备案域名、免费额度足够小工具跑，还能直接接收虚拟支付的发货推送回调。

① 前端 wx.login 拿 code → 云函数换 openid + session_key
② 前端点"买 ¥1 额度包" → 云函数生成订单号 + 算双签名 → 返回参数
③ 前端 wx.requestVirtualPayment(...) → 用户付款
④ 微信发货推送 → 云函数验签 → 数据库余额 +10 分钟（必须做幂等，按订单号去重）
⑤ 前端查余额 → 转歌时云函数扣减分钟数 → 放行处理

关键原则：前端返回的 success 只算"弱确认"，一律以后端订单状态为准；回调 + 主动查单双通道兜底，防止掉单。

四、广告失败自动放行（第 3 条需求）

这条不仅"能做"，而且强烈建议做——广告填充率不可能 100%，尤其新小程序初期广告池不稳，硬卡住只会让用户白流失。

完整状态机

① 广告实例创建失败（未开通流量主 / 基础库过低 / 返回 null）→ 直接放行，不提示
② load() 失败 或 onError（如 1004 无广告填充）→ 放行 + 轻提示"今天广告已用完，本次免费为您处理"
③ 用户中途关闭视频（isEnded = false）→ 不放行，提示"需要看完才能继续哦"，允许重看
④ 多广告序列中途失败（比如要 2 个，第 2 个拉不到）→ 已看的算数，剩余直接放行（绝不能让用户白看）
⑤ 加载超过 8 秒没响应 → 按失败处理，直接放行

风控补充：防止有人断网刷免费次数，可加"广告失败放行每日上限"（如 3 次/天，本地计数即可），超限则引导付费或稍后再试。首版不做也行，上线后看数据再补。

// 广告解锁核心逻辑（示意）
async function unlockByAd(needCount) {
  const ad = wx.createRewardedVideoAd && wx.createRewardedVideoAd({ adUnitId })
  if (!ad) return true            // ① 能力不可用 → 放行

  for (let i = 1; i <= needCount; i++) {
    const ok = await new Promise(resolve => {
      const timer = setTimeout(() => resolve(false), 8000)   // ⑤ 超时兜底
      ad.onClose(res => {
        clearTimeout(timer)
        resolve(res && res.isEnded === true)                 // ③ 没看完不算
      })
      ad.onError(() => { clearTimeout(timer); resolve(false) }) // ② 加载失败
      ad.show().catch(() => { clearTimeout(timer); resolve(false) })
    })
    if (!ok) {
      // ④ 中途失败：已看的不浪费，剩余直接放行
      return i > 1 ? true : (await allowFreeByAdFailure())   // ② 首条失败也放行
    }
  }
  return true
}

六、要开通的东西（按顺序）

  1. 小程序类目必须含「工具」（虚拟支付只开放给工具/文娱/社交/资讯/深度合成等类目；我们选的"工具-音视频处理"正好符合 ✅）
  2. 完成小程序认证 + ICP 备案（个人主体 30 元/年，也能开虚拟支付，但月限额 10 万；企业/个体户无限额）
  3. MP 后台 → 支付与交易 → 虚拟支付 → 开通：拿 AppID、OfferID、现网 AppKey（沙箱 AppKey 仅测试用）
  4. 打开"苹果支付"开关并补齐 Apple IAP 资料 —— 很多人漏这步，不开的话 iOS 下单直接失败
  5. 道具管理里建 4 个道具（¥1 体验包 / ¥3 常用包 / ¥6 超值包 / ¥9.9 包月卡），发布到现网（约 10 分钟生效）。建包月卡时验证 ¥9.9 是否合法，不合法改 ¥9.5
  6. 开通流量主（累计 UV ≥ 1000）拿广告位 ID —— 这条和付费不冲突，可以并行推进

注意：虚拟支付商户号是独立的一套，和普通微信支付分开结算（T+3；iOS 由苹果月结，约 45~60 天）。
