## 1. 环境选择：优先微信云开发，不要绕腾讯云 CloudBase

### 1.1 本次踩的坑

一开始在腾讯云 CloudBase 控制台创建了环境 `tiaodiao-d3g2litjz17d2a885`：

- 腾讯云环境默认是 **PostgreSQL**，`wx-server-sdk` 的 `db.collection` 需要先开通 **Document 插件**（`pgdoc_data` schema）才能用。
- 函数部署后，控制台“测试”能跑，但小程序里 `wx.cloud.callFunction` 报：

```
-601034 没有权限，请先开通云开发或者云托管
```

原因是小程序还没有开通**微信云开发**。微信云开发开通后又自动生成了新环境 `tiaodiao-d2gx2mgmwaf534c61`。

- 此时继续用腾讯云环境 ID 调用，会报：

```
-501000 Environment not found
```

腾讯云环境需要在微信云开发控制台「设置 → 环境设置 → 管理我的环境 → 使用已有腾讯云环境」导入，小程序才认识。本次没有继续走导入，而是**直接把函数部署到微信云环境**，问题归零。

### 1.2 结论

- 个人主体小程序做虚拟支付，**优先在微信开发者工具/微信云开发控制台开通环境**，环境天然被 `wx.cloud` 认识。
- 腾讯云 CloudBase 控制台建的 env 不是不能用，但要多一步导入；如果只是给小程序用，没必要绕。
- 腾讯云环境 `tiaodiao-d3g2litjz17d2a885` 目前未使用，可后续删除。

## 2. 双签名与下单（核心，最容易写错）

### 2.1 官方公式（2026-11 核对）

```
paySig    = HMAC-SHA256(AppKey, "requestVirtualPayment&" + signData)
signature = HMAC-SHA256(session_key, signData)
```

- `AppKey`：MP 后台 → 虚拟支付 → 基本配置 → 现网 AppKey（`env=0`）
- `session_key`：云函数用前端 `wx.login` 的 code 调 `jscode2session` 换取
- `signData` 必须是**同一个字符串**前后端原样传递，一个字符都不能差

### 2.2 signData 必填字段

```json
{
  "offerId": "1450705879",
  "buyQuantity": 1,
  "env": 0,
  "currencyType": "CNY",
  "productId": "pkg_60",
  "goodsPrice": 100,
  "outTradeNo": "T...",
  "attach": "pkg_60"
}
```

注意：

- `offerId` 必须是**字符串**（数字会签名失败）
- `goodsPrice` 单位是**分**，必须与 MP 后台道具价格完全一致，否则 `-15013`
- `attach` 必填，发货推送会原样带回
- `outTradeNo` 8~32 位，只能用数字/字母/`_-|*@`，不能以下划线开头
- `env=0` 现网；`env=1` 沙箱**仅开发者工具可用**，真机/体验版会被拦

### 2.3 原骨架的致命 bug

项目早期骨架把两套密钥用反了：

- `paySig` 用了 `session_key`
- `signature` 用了 AppKey

只翻 `PAY_ENABLED` 开关是永远跑不通的。本次已全部重写，并用官方文档里的 Python 示例固定输入校验过：

- `pay_sig = c37809...`、`signature = 089d9e...`，Node HMAC 结果与官方逐字符一致。

### 2.4 常见错误码

| 错误码 | 含义 | 处理 |
|---|---|---|
| `-2` | 用户取消 | 不提示，正常返回 |
| `-15005` | signature 错误 | session_key/code 问题 |
| `-15006` | paySig 错误 | AppKey 与 env 不匹配，或 signData 不一致 |
| `-15007` | session_key 过期 | 重新 `wx.login` 再下单 |
| `-15010` | 道具未发布 | 后台发布道具 |
| `-15011` | 现网用了沙箱 | `env` 改 0 |
| `-15013` | 价格不一致 | config/createOrder/MP 后台三处同步 |
| `-15014` | 道具发布未生效 | 等约 10 分钟 |
| `-15016` | signData 格式错误 | 检查字段类型 |

## 3. 发货与到账

### 3.1 原则

- `wx.requestVirtualPayment` 的 success **只是弱确认**，可能丢失（微信异常退出等），**不能作为发货依据**。
- 发货只认两条路：
  1. 发货推送 `xpay_goods_deliver_notify`
  2. 主动查单 `/xpay/query_order`（status 2/3/4 补发货）
- 官方要求：推送和轮询**至少实现一个**。

### 3.2 onDelivered 幂等

- 用 `deliveries` 集合，`_id = outTradeNo` 作为发货锁。
- `add` 成功才发货；重复推送抢不到锁直接回成功。
- 发货成功但订单状态更新失败时**不要释放锁**，否则重推会重复到账。
- 返回 `{ ErrCode: 0, ErrMsg: "success" }`；非 0 微信会重推最多 15 次。

### 3.3 queryOrder 查单

```
POST https://api.weixin.qq.com/xpay/query_order?access_token=...&pay_sig=...
pay_sig = HMAC-SHA256(AppKey, "/xpay/query_order&" + body)
body = {"openid":"...","env":0,"order_id":"outTradeNo"}
```

- `order.status`：0/1 未支付，2 已支付待发货，3 发货中，4 已发货，6 已关闭
- 2/3/4 都触发幂等发货

### 3.4 本次的 30 秒延迟事故

**现象**：用户支付成功后等了约 30 秒才到账，以为钱丢了。

**根因**：没配发货推送；旧 `pay.js` 先干等 10 次权益轮询（10×1.2s + 云调用耗时）才去调 `queryOrder`，到账确认被拖到 30 秒。

**修复**：

- 支付成功后**立刻并行**启动 `queryOrder`：首次 1.2s，之后 2.5~5s 重试（`queryBusy` 防并发）
- 同时每秒轮询 `getEntitlement`
- 模拟器计时：支付成功 → 到账 **3.0 秒**
- 如果要 1 秒级到账，再配发货推送：云开发控制台 → 设置 → 其他设置 → 消息推送 → 云函数 → `xpay_goods_deliver_notify` → `onDelivered`

### 3.5 前端等待 UI（本次新增）

- 等待层：`正在确认支付结果` → `正在更新你的权益` → `已到账`
- **权益确认前等待层不消失**，避免用户以为钱丢了
- 延迟兜底：`支付已成功` + `刷新权益` 按钮
- 到账庆祝：彩带 + `充值成功` + `+60 分钟` + `尊贵的付费用户` + `返回下载`
- 成功卡主按钮 `返回下载`（`navigateBack` 回解锁/下载页），次要 `留在此页`

## 4. 密钥与部署（最容易复发）

### 4.1 本次方案：部署包注入 `secrets.js`

微信云环境不方便给每个函数配环境变量，所以 `createOrder / queryOrder` 支持：

```js
let LOCAL_SECRETS = {}
try { LOCAL_SECRETS = require('./secrets.js') } catch (e) {}
const OFFER_ID = process.env.OFFER_ID || LOCAL_SECRETS.OFFER_ID || ''
// APP_KEY / APPSECRET 同理
```

部署前生成（**不入 git**）：

```js
// cloudfunctions/createOrder/secrets.js
module.exports = {
  OFFER_ID: '...',
  APP_KEY: '...',
  APPSECRET: '...',
  PAY_ENV: '0',
  APPID: 'wx0e7879a4c7d37c39',
}
```

`.gitignore` 已排除：

```
cloudfunctions/createOrder/secrets.js
cloudfunctions/queryOrder/secrets.js
tools/pay-secrets.json
```

### 4.2 血泪教训：全量部署会覆盖 `secrets.js`

后来给 6 个函数补 `config.json {"timeout":60}` 时做了一次全量部署：

```bash
cli cloud functions deploy --env <env> --names login createOrder onDelivered queryOrder getEntitlement consume ...
```

`createOrder / queryOrder` 的部署包被没有 `secrets.js` 的本地目录覆盖，支付立刻报：

```
支付还没配置好（缺 OFFER_ID/APP_KEY）
```

**规则：带密钥注入的函数不能参加全量部署。**

`tools/deploy-pay.sh` 已改成：

- 自动部署 4 个无密钥函数：`login / onDelivered / getEntitlement / consume`
- `createOrder / queryOrder` 只有在 `secrets.js` 存在时才单独部署
- 缺 `secrets.js` 时跳过并打印警告

### 4.3 密钥来源

- `OFFER_ID`、现网 `APP_KEY`：MP 后台 → 虚拟支付 → 基本配置
- `APPSECRET`：MP 后台 → 开发管理 → 开发设置（只显示一次/可重置）
- 腾讯云旧环境的环境变量可作为临时备份来源；读取时注意不要打印到聊天/日志
- 不要把密钥写进前端、文档、commit

### 4.4 控制台测试的假失败

腾讯云/云开发控制台“测试”没有微信用户上下文，`cloud.getWXContext().OPENID` 为空：

- 查询 `where({ _openid: '' })` 可能直接抛错
- 集合不存在时也会报 `DATABASE_COLLECTION_NOT_EXIST`

**判断支付/权益是否正常，以模拟器或真机 `wx.cloud.callFunction` 为准，不要只看控制台测试结果。**

## 5. 前端三档与广告

### 5.1 三档结构

1. **限时免费**：`感谢您关注 亢铨宝 视频号`
2. **额度下载**：`当前余额 N 分钟，本次消耗 N 分钟` + `限时优惠 1 元得 60 分钟`
3. **包月下载**：`30 天无限量` + `不用看视频，不用算分钟数`

默认选中：包月 > 额度 > 限时免费。底部按钮只显示当前档位名（单行）。

### 5.2 `AD_ENABLED` 不等于有视频

只把 `AD_ENABLED=true` 不会自动有广告，还需要：

1. 流量主开通（UV ≥ 1000 + 审核）
2. MP 后台创建激励视频广告位，拿到 `adunit-...` 填 `AD_UNIT_ID`
3. 广告位审核通过、有广告库存

否则 `getAd()` 返回 null，走“广告失败放行”，还是免费。当前 `AD_ENABLED=false`，限时免费档直接放行，是活动逻辑；以后开广告要同时改文案和行为。

另外 `PAY_ENABLED=true` 时失败放行会调 `grantAdFail` 云函数，目前该函数未部署，会走 catch 直接放行，每日上限未生效。认真做广告前要补。

### 5.3 平台路径

「是否启用平台路径」与支付无关，只影响订阅消息跳转、发现页推荐落地页；保持关闭。

## 6. 试听内存优化（3 分钟）

### 6.1 旧问题

3 分钟试听一次生成 180 秒 PCM：

- Worker 交错 Float32：约 63MB
- 主线程再建同尺寸 AudioBuffer：约 63MB

低端机直接 OOM。

### 6.2 当前方案

`audio.js playPreviewChunked`：

- 每片 **10 秒**，Worker 逐片变调回传
- 主线程最多预取 **2 片**（约 7MB）
- 每片首尾 **8ms 淡入淡出**，避免切片边界“咔哒”
- 播完的 source 立即 `onended` 从队列移除，避免 18 个 AudioBuffer 累积
- 短歌从当前指针起播（旧 `duration - PREVIEW_SEC` 钳位会把短歌强制归零）

### 6.3 验证

- 8 项交互：起播/进度/暂停/续播/改调/重唱/离开无残留
- 25 秒跨 3 个切片连播：进度 5/10/15/20/25，无断流

## 8. 发布流程与 git 踩坑

### 8.1 本地仓库是 tarball 根提交

本地仓库是“恢复自远程 tarball”的**根提交**，和 `origin/main` 没有共同祖先，直接提 PR 不行。

正确流程：

```bash
git stash push -u -m "wip"
git checkout -b feat/xxx origin/main
git stash pop
git add -A
git commit -m "..."
git push -u origin feat/xxx
gh pr create --base main --head feat/xxx ...
gh pr merge <n> --merge --delete-branch
```

### 8.2 清理未跟踪文件的坑

`git clean -fd tools/tutorial` 会删除未跟踪的 `build/`、`out/` 生成物（本次教程视频生成物被清掉；源码和 `.env` 还在，可跑 `build.py` 重建）。

**清理前先确认哪些是生成物、哪些要保留；忽略文件也可能被 `-f -d` 连带删掉。**

### 8.3 上传 ≠ 提交审核

- `cli upload` 只生成开发版本；体验版需 MP 后台「版本管理 → 开发版本 → 选为体验版」
- 提交审核也在 MP 后台「版本管理 → 开发版本 → 提交审核」
- 测试截图/二维码等生成物不要进 PR；`tools/autotest/shots/*.png` 已用本地 exclude 隐藏

## 10. 当前配置快照

```js
// miniprogram/config.js
PAY_ENABLED: true,
AD_ENABLED: false,
CLOUD_LOGIN_ENABLED: true,
CLOUD_ENV: 'tiaodiao-d2gx2mgmwaf534c61',

  { id: 'pkg_60',    price: 100, minutes: 60, name: '60 分钟' },
  { id: 'pkg_month', price: 990, monthly: true, name: '包月' },
],
```

云函数：

- `login`：返回 openid / 管理员判定
- `createOrder`：code2session + 双签名 + 落单
- `onDelivered`：发货推送/JSON/XML，`deliveries` 幂等
- `queryOrder`：`/xpay/query_order` 查单，status 2/3/4 补发货
- `getEntitlement`：包月/分钟权益

部署（只部署无密钥函数）：

```bash
tools/deploy-pay.sh <ENV_ID>
```

单独更新带密钥函数：

1. 生成 `cloudfunctions/createOrder/secrets.js`、`queryOrder/secrets.js`
2. `cli cloud functions deploy --env <ENV_ID> --names createOrder queryOrder --project ... --remote-npm-install`
3. 删除本地 secrets 文件
